# BranchChat

BranchChat is a local-first interface for structuring AI conversations as a visual tree. It lets a discussion split into independent paths without losing the main thread.

The project focuses on conversation structure and navigation. It does not create, train, improve, or compete with AI models. Responses are generated by an external model through the user's own API credentials.

## Current functionality

- Stream AI answers answers OpenRouter.
- Continue a normal conversation as a vertical question-and-answer chain.
- Create left or right branches from any completed node.
- Continue sibling and nested branches independently with isolated context.
- Arrange branches automatically and connect their origins visually.
- Pan horizontally, scroll vertically, zoom from the toolbar, and return to the origin.
- Retry failed requests with actionable provider errors.
- Save conversation trees to local SQLite storage.
- Reopen, rename, continue, or delete conversations from local History.

## Local-first design

BranchChat is intended to be cloned and run on the user's own computer.

- No account or login is required.
- No cloud database is required.
- Conversation history is stored in `data/branchchat.db`.
- AI credentials are read by the local server from `.env.local`.
- The browser never receives the API key.
- Development and production commands bind to `127.0.0.1` by default.

OpenRouter and the selected model provider remain external services. API requests may incur charges on the user's OpenRouter account.

## Requirements

- Node.js 20.9 or newer
- npm
- An OpenRouter account, API key, and access to a selected model

## Install and run

From the repository directory, install the dependencies:

```bash
npm install
```

Create a file named `.env.local` in the same directory as `package.json`:

```env
OPENROUTER_API_KEY=your_openrouter_api_key
OPENROUTER_MODEL=provider/model-name
```

To obtain these values:

1. Sign in to OpenRouter and create an API key from its account dashboard.
2. Choose a model from the OpenRouter model catalog.
3. Copy its exact model identifier, normally in `provider/model-name` form, into `OPENROUTER_MODEL`.
4. Keep the key private. Do not commit or share `.env.local`.

Start the development server:

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

Restart the server after changing `.env.local`. BranchChat displays the active provider and model below its title. Changing the configured model affects future replies, including replies added to an older conversation; existing answers are not regenerated.

## Production run

Build and start the local production server:

```bash
npm run build
npm run start
```

Then open [http://localhost:3000](http://localhost:3000).

## Local data and backup

The SQLite database is created automatically at:

```text
data/branchchat.db
```

The `data/*.db*` files and `.env.local` are ignored by Git. To make a manual backup, stop BranchChat and copy the `data` directory to a safe location. Deleting a conversation from History permanently removes that conversation and its branches from the local database.

Each AI request rebuilds the relevant branch history and sends that context to the currently configured model. Sibling branches are excluded, while ancestor history up to the branch origin is preserved.

## Current scope

- OpenRouter is the only directly supported provider.
- API credentials are configured through `.env.local`; there is no settings screen for keys yet.
- BranchChat is single-user and local by default.
- Exposing the server to a LAN or the public internet is outside the current security model.
- Individual nodes and branches cannot be deleted; complete conversations can be deleted from History.
